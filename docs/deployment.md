# Deployment

Life Recorder deploys as a single Cloudflare Worker (TanStack Start SSR + server
functions) backed by a Cloudflare D1 database. There is no separate backend
process — auth, preferences, records, and SSR all run in one Worker.

## Prerequisites

- A Cloudflare account with Workers and D1 enabled.
- The `wrangler` CLI (installed as a dev dependency; use `npx wrangler`).
- A GitHub OAuth app for sign-in (Settings → Developer settings → OAuth Apps).

## 1. Create the D1 database

```bash
npx wrangler d1 create life-recorder-db
```

Copy the returned `database_id` into [`wrangler.jsonc`](../wrangler.jsonc),
replacing `REPLACE_WITH_D1_DATABASE_ID`.

## 2. Apply migrations

Migrations are generated by Drizzle Kit into `src/db/migrations` and applied
with Wrangler.

```bash
# Regenerate SQL after any schema change:
npm run db:generate

# Local (for `npm run dev` against a local D1 file):
npm run db:migrate:local

# Remote (production D1):
npm run db:migrate:remote
```

## 3. Configure the GitHub OAuth app

- **Homepage URL:** your deployed URL (e.g. `https://life-recorder-new.<account>.workers.dev`)
- **Authorization callback URL:** `<deployed-url>/api/auth/callback/github`

For local development the callback is `http://localhost:3000/api/auth/callback/github`.

## 4. Set secrets

Local development reads `.dev.vars` (copy from
[`.dev.vars.example`](../.dev.vars.example)). For production, set Wrangler
secrets:

```bash
npx wrangler secret put BETTER_AUTH_SECRET   # a long random string
npx wrangler secret put BETTER_AUTH_URL       # your deployed https URL
npx wrangler secret put GITHUB_CLIENT_ID
npx wrangler secret put GITHUB_CLIENT_SECRET
```

`BETTER_AUTH_URL` must match the deployed origin so OAuth callbacks and session
cookies resolve correctly. Cookies are issued `httpOnly`, `secure`, `sameSite=lax`.

## 5. Validate and deploy

```bash
npm run typecheck
npm test
npm run build
npx wrangler deploy --dry-run   # validate bindings without uploading
npm run deploy                  # build + wrangler deploy
```

## 6. Deployed smoke test (manual gate)

After deploying, verify in a browser — no separate backend should be running:

1. The SSR home route loads and shows the timer shell.
2. GitHub sign-in completes and the session survives a reload.
3. Changing a preference persists across reloads.
4. Completing a timer records an entry that appears in History.
5. Session cookies show `Secure` + `HttpOnly` in dev tools.

> These steps require real Cloudflare and GitHub OAuth credentials, so they are
> a manual gate rather than an automated check.

## Fallback paths

If a Cloudflare runtime limit (not implementation effort) blocks the demo:

- **Database:** swap D1 for a free Postgres (Neon/Supabase) behind the same
  repository interfaces in `src/server/repositories/`.
- **Auth:** swap Better Auth for Auth.js while preserving the session contract.
- **Hosting:** deploy to Vercel and document the tradeoff.

See the plan's *Resolved Planning Decisions* for the rationale behind each
default and its fallback.
